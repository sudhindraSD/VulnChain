## 1. Amendment note — the earlier gate was set against a leaky comparator

The original pre-registered success bar lives in `phase5/part_c_masked_edge_multiseed.py`
(lines 146–147, 171):

```text
margin            = max(0.02, 2 * std(label_prop))
success_threshold = mean(label_prop) + margin
model_passes_criterion = mean(model_auc) >= success_threshold
```

Its `label_prop` is `TrainModel/masked_edge_audit.py::run_label_prop_baseline` fed the
**original, unmasked** `phase4/vpss_labels_51repo.json`. The published outcome
(`phase5/part_c_masked_edge_audit_5seeds.json`) is:

| Comparator (original gate) | Mean ± Std ROC-AUC | Margin | Success bar | VulnGAT-HR | Verdict |
|---|---|---:|---:|---:|---|
| `LP_original` | 0.719099 ± 0.006897 | 0.020000 | 0.7390986791551671 | 0.631473 ± 0.004468 | **FAIL** (`model_passes_criterion: false`) |

**The leak was discovered after that gate had already failed.** `phase5/LP_LEAKCHECK.md`
(generated by `TrainModel/masked_edge_audit_leakfix.py`) shows that LP used the **masked**
graph for neighbourhoods but the **original** closure labels for label values. VPSS is a
closure label, so a masked package's parents still carry its hidden CVE and LP averages the
answer back in. Recomputing VPSS on the masked graph removes this information and changes
the comparator by **−0.086194**:

| Comparator (amended gate) | Mean ± Std ROC-AUC |
|---|---|
| `LP_clean` (VPSS recomputed on masked graph) | 0.632905 ± 0.007867 |
| VulnGAT-HR (unchanged) | 0.631473 ± 0.004468 |
| BFS (unchanged, for reference) | 0.528650 ± 0.003851 |

**Therefore:** the earlier gate was set against a leaky comparator and is **superseded**, not
silently re-scored. The comparator for all future adjudication on this protocol is
`LP_clean`. **Both are reported in the paper**: the original gate (LP_original + 0.02 =
0.739099, fail) and the amended gate defined in §2, with the leak-check reference. No
setting of the failed gate is retroactively adjusted.

## 2. The gate (amended, fixed before any hybrid exists)

For each seed `s ∈ {42, 123, 456, 789, 1024}`, on **one identical mask instance** —
the same `apply_edge_mask(data, eligible, pkg_id_to_idx, graph_json, cve_id_to_idx, 0.50, s)`,
the same positive set `pos_s`, the same negative set `never_vuln_indices`, and the same
masked `HeteroData` — compute both AUCs with the **official**
`TrainModel/masked_edge_audit.py::compute_auc` (Wilcoxon–Mann–Whitney, ties = 0.5):

```text
delta_s = AUC(hybrid_s) - AUC(LP_clean_s)
```

Let `std_pop(LP_clean)` be the **population** standard deviation (`np.std`, `ddof=0`) of the
five `LP_clean` AUC values, matching the published five-seed script.

> **PASS iff** `mean_s(delta_s) > max(0.02, 2 * std_pop(LP_clean))`

Equivalently, using the already-published comparator numbers at registration time
(`std_pop(LP_clean) = 0.007867`, so `max(0.02, 2σ) = 0.02`):

> **PASS iff** `mean_s(AUC(hybrid_s)) > 0.632905 + 0.02 = 0.652905`

Both forms are registered; the paired-difference form is primary. The numeric bar
`0.652905` is **frozen at registration** from published comparator values and must not be
recomputed from, or adjusted to, any hybrid result. Paired-by-seed is mandatory: an
unpaired comparison of two independent means is not a valid adjudication of this gate.

Fixed protocol items, all unchanged from `phase5/LP_LEAKCHECK.md`:
`phase5/bench_run/vulnchain_graph.json` (12,405 packages),
`phase4/vpss_labels_51repo.json`, `phase4/repo_split_mapping_51repo.json`,
`phase5/models/vulngat_hr_full.pt` with `Package.x[:, 6]` zeroed for masked packages,
`N_eligible = 645` and `N_never_vuln = 8,682` with the hard assertions retained.

## 3. Mandatory leak-free construction of the hybrid's correct step

**The hybrid's correct step must use VPSS labels recomputed on the masked graph
(`data_pipeline/vpss_labeler.label_all()` called on the masked graph), never the original
labels.**

Concretely, for each seed:

1. Build the masked graph with every `hasVulnerability` edge whose source is a masked package
   removed; `dependsOn`, all node features, CVE nodes, and all other edges are untouched.
2. Call `vpss_labeler.label_all()` on that masked graph for **all** packages (the official LP
   also needs the global mean for its no-neighbour fallback).
3. Feed those recomputed labels to any label-consuming component — this is exactly `LP_clean`.

Passing `phase4/vpss_labels_51repo.json` (or any label set derived from the unmasked graph)
to a hybrid component reintroduces the closure-label leak documented in
`phase5/LP_LEAKCHECK.md` and **invalidates the gate**. A hybrid that fails this construction
requirement is not adjudicated; it is reported as a protocol violation.

## 4. Pre-declared fallback (no tuning after the fact)

If `mean_s(delta_s) <= max(0.02, 2 * std_pop(LP_clean))`, the outcome is recorded and
published as a **negative result**. On these five seeds there will then be:

- no weight search, weight refitting, or per-seed weight choice;
- no threshold or margin adjustment, and no substitution of `LP_original` for `LP_clean`;
- no seed exclusion, re-masking, re-splitting, or post-hoc stratum selection;
- no architecture or hyperparameter tuning driven by these seeds;
- no further tuning of any kind on these seeds.

The per-seed paired differences, their mean, the realized margin, and the failing comparison
are published verbatim. Any later hybrid idea would require a **new pre-registration on
different held-out seeds or data**, with this negative result cited.

## 5. Known limitations carried into the paper

These are protocol properties, not defects to be silently repaired during adjudication. They
must appear as limitations in the paper alongside any hybrid result or negative result.

1. **`compute_own_vpss` unit mismatch → `N = 645`.** It computes `own_raw = Σ CVSS/10` but
   divides by `raw_sum`, which the labeler stores as `Σ CVSS` (unscaled). `own_ratio` is
   therefore ~10× too small, so nothing passes the declared 0.70 threshold and
   `select_eligible_packages` takes its documented **auto-relaxation to 0.30**. That
   relaxation, not the nominal threshold, is what produces `N_eligible = 645`. Preserved
   verbatim; see `phase5/LP_LEAKCHECK.md` §7.3.
2. **Mask semantics.** `apply_edge_mask` does **not** remove 50% of `hasVulnerability`
   *edges*. It draws a Bernoulli(0.50) per **eligible package** and removes **all** of that
   package's CVE edges (plus a forced floor of 3 masked packages). So roughly half of the
   eligible packages lose every CVE edge; the number of edges removed varies by seed
   (752–882 in the leak-check run). The phrase "50% masked-edge audit" must be qualified
   accordingly in the paper.
3. **Negatives are shared from the original labels.** `never_vuln_indices` comes from
   `phase4/vpss_labels_51repo.json` for every method, including `LP_clean` and any hybrid,
   and is **not** recomputed on the masked graph. This keeps comparisons on identical masks
   and matches the official protocol, but it is a limitation: the negative class is defined
   by unmasked closure labels.

The full list of code-vs-description discrepancies (LP docstring overstating edge types,
BFS rank-invariant constant normalizer, `idx_to_pkg_id` unused) remains in
`phase5/LP_LEAKCHECK.md` §7 and is incorporated by reference. The distribution-shift caveat
from `TrainModel/masked_edge_audit.py` also still applies: the as-trained model never saw
deliberately deleted `hasVulnerability` edges during training.

## 6. What this registration does *not* do

- It does **not** define, endorse, or describe a hybrid architecture, fusion rule, or weight
  vector. It fixes only the decision rule and the leak-free construction requirement.
- It does **not** adjudicate any gate. `phase5/LP_LEAKCHECK.md` explicitly does not
  re-adjudicate the original gate, and this document does not re-adjudicate it either.
- It does **not** report any hybrid result. No hybrid code exists at registration time.
